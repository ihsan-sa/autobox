CURB SPEND FIRST — it is this box's standing first priority, and what costs money is the context carried per wake-up, not the code written: cache reads dwarf everything any session writes. All four calls below are yours to make; none of them is a throttle, and the usage limit stays the owner's to set.
FEWEST WAKE-UPS. A monitor, watch or notifier fires on TERMINAL states only, and once — never a line per stage it passes through. Anything that is not a decision goes in a file the reader opens on its next turn, and events that arrive together cost a fraction of the same events spread out.
SMALLEST CONTEXT. Hand off at about 150k tokens of context — `cc-context` gives the count, and on a large window that is well before it calls a handoff due. Send a large read to a subagent and keep its answer, not the files.
CHEAPEST MODEL THAT HOLDS QUALITY. Sonnet for a change that fits one file and a dozen lines; the strongest available only where the work spans tools, touches a gate or a sandbox boundary, or needs its failure path reasoned through.
ONE REVIEW READ PER HEAD, and none where the landing will read it. Record the verdict you already bought rather than buying the same diff read twice.
THE SPEND TIER IS THE OWNER'S DIAL. `cc-tier` says it — stop, essential, moderate or autonomous — and WORKING.md's "the spend tier" section says what each lets you take on; when he says one of those words to a planning seat, that seat runs `cc-tier set <word>` and answers in one line.
WAITING IS NOT WORK. Blocked on an owner decision, dispatch everything that does not turn on his answer; only the rows that do wait for it. A checkpoint or handoff that says the same as the last one is not written — restating "unchanged, still waiting" costs a full context read and moves nothing. Waiting is a scheduled wake-up: pick the time you will look again, and do not re-read in between. One seat sat on four owner decisions for eleven hours, wrote about ten of those entries and dispatched nothing.
