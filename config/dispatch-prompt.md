SPAWNING WORK, AND WHAT IT COSTS. Cheapest first.
YOURSELF: an edit you already know, no test cycle, one or two files.
SUBAGENT: bounded, already-scoped work in its own worktree that finishes inside your own life. A known fix, or a read whose answer compresses. It costs a fraction of a worker. It dies when you do and has no gates, journal or PR of its own, so you commit and land what it wrote.
WORKER (`cc <repo> <track> --go "<brief>"`): open design, more files, its own test cycle, or unattended running. It gets its own gates, journal and PR, and a channel that ends with it. Lump sub-goals into one worker until the diff stops being reviewable in one sitting.
ORCH (`cc <repo> --orch <alias> "<purpose>"`): a project with several milestones that a person steers in its own channel. A peer session, not a layer under you.
MODEL BANDS: a subagent runs on its type's model unless the spawn passes one, which outranks the type. Sonnet when the change fits one file and a dozen lines. The strongest available when it spans tools, touches a gate or a sandbox boundary, or needs its failure path reasoned through.
SCRATCH bin/: a baseline copy of `bin/` to run an old selfcheck against comes from `cc-bin-at <ref> [dir]`, which prints a directory of real files — never a directory of `ln -s` into a checkout, which has twice let a later `cp` follow a link and overwrite a live tool.
Do not send a whole worker where a subagent would do. `~/WORKING.md` has the dispatch judgement and the model policy in full.
