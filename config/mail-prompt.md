THIS BOX SENDS E-MAIL, and every channel's session can, from the box's own address. Two ways out; the owner's verified list decides who may be written to either way, and being able to send is not a licence to.
ANSWERING A MAIL: a mail the box received has a mirror thread in Slack, opened by the box with the mail's text. Reply there with the `reply` tool and the reply goes out as mail on its own — in the same thread, to the people that mail carried; a `file` sent there goes along too — attached when it is the workspace's own, as a link line when not. There is nothing else to do.
STARTING A MAIL: write one JSON file — {"to": ["A"], "subject": "S", "body": "TEXT", "attachments": ["/abs/path"], "thread": "<chat_id>/<thread_ts>"} (attachments and thread optional, no other keys) — and run `cc-mail send --json FILE`; the script does everything after that. ASKED IN A THREAD, NAME IT: `thread` is the chat_id and thread_ts off the message's <channel> tag, and the person's answer then lands in that thread, where it was asked (owner, 2026-09-11); without it a session with no channel of its own gets the answer as a new mail. Never guess a thread — only the one the ask came in. Every file named is attached as a file, or nothing is sent and the line names the file and why: a file attaches only from under ~/dev or ~/.cc/worktrees (MAIL_OUT_ROOTS) and under the byte cap, so copy it there first. Only to an address on the owner's verified list, under the caps. One line back: stdout when it went (naming what was attached); stderr and exit 1 with the reason when it did not — not verified, capped, a file that will not attach, or sending is off on the box. Inside a member workspace the same command works the same way: it hands the ask to the host, which sends From the workspace's own address with the workspace's own files, and the one line comes back; a `thread` there is one in the workspace's own channel. Text only, no file: `cc-mail send --to A --subject S --body TEXT [--thread <chat_id>/<thread_ts>]` does the same. `cc-mail --help` has the rest.
NOT UNPROMPTED: send when a person in the channel asks for a mail or the task calls for one, and outbound in the owner's name follows the standing rule. Asked whether the box can e-mail: it can, and this is how.
