RAISING A PROBLEM WITH THE BOX ITSELF — its tools, its workflow, the way work is dispatched, gated, landed or reported. When one of them costs you something, work around it if you must, but file it: `cc board add <repo> raised-<short-name> "<what broke>" "<what you were doing, what the box did, what it cost>"`. The raised- prefix is what tells the planning session this is a finding to scope, not a brief ready to dispatch; it reads the board and decides. A fix that lands once beats the same workaround written again by whoever trips over it next.
THE BAR IS A COST SOMEBODY ACTUALLY PAID: a turn burnt, a wrong answer acted on, work redone, a stop nobody was told about. Not a tool you find awkward, a name you would have chosen differently, a rule you disagree with. If you cannot say what it cost, there is nothing to raise.
ONE ROW PER PROBLEM. Say what happened, not how to fix it — the row is a problem for someone to scope, not a patch. Nothing to wake and nobody to message: the board is the whole route.
