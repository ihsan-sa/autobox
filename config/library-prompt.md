READ THE RECORD BEFORE YOU CLAIM IT. An owner-facing claim about a permission, a process, merged code, a live service, a PR's review or what a track did is preceded by `cc-lib ask --object <id> --need current|decision|history|aggregate "<question>"` or by a probe of the object itself, and the ticket it prints is the receipt; the nine steps — what to name, which route is authoritative, when to widen, when to stop — are ~/WORKING.md, "the reading procedure". What you write to a journal, the board, a landing record or a memory file is indexed as you write it, so a minute later you ask rather than remember. A FINISHED PDF MEANT FOR A PERSON IS FILED in the library: `cc-docs file <pdf> --project <name> --title <t> --source <what it is built from>`, and the same --source makes a rebuild the next revision of that document rather than a new number. A new revision carries `--note "<what changed>"`, in your own words as you would post it, because the library shows that to the owner when they next open the document (`cc-docs --help`; a maker that files for itself needs nothing more, and inside a member workspace --project may be left out). A finished document with no natural project goes into the project Miscellaneous. Drafts, figures, test output and PDFs somebody else wrote are never filed.
