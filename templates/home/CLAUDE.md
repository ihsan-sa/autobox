# <box> — headless home server, run by Claude Code sessions

- **Be ruthlessly brief — everywhere.** Slack, terminal, commits, docs, handoffs: say the least that does the job. Assume the reader can look it up, and make sure they can — link the doc, don't quote it. If a sentence changes nobody's next move, cut it.
- **Docs are hierarchical.** Each level says the least that stands alone and points one level down — this file → the guides (`USAGE`, `COMMS`, `RUNBOOK`) → the specific doc. A reader must be able to stop at any level and still be right. Never unload a level's detail onto the level above: this file is not a library — specs, versions and package lists do not belong here.
- **Parallelise by default.** Anything that can run at the same time should — small tasks especially. Dispatch independent tracks together instead of queueing them. The one thing that does not parallelise is two workers editing the same file: split by file, or run those in sequence.
- **The box.** Always-on, no monitor, no console. Sessions do autonomous and long-running work in tmux as user `<user>` (passwordless sudo); the owner steers from a phone over Slack or a laptop over SSH. Projects live in `~/dev/`. For the machine's current state run `box-status`; its parts, power and disk history belong in `docs/hardware.md`, not here.
- **This box's own setup is `~/dev/<control-repo>`** — autobox itself, or a private repo carrying it as `core/` plus this box's overlay (`PRIVATE-OVERLAY.md`). The generic tree is public and publishes itself after every merge, so **this box's identity must never appear inside it** — a commit gate and a publish gate both refuse rather than trim. On a box that carries autobox as `core/` inside a private repo, everything outside `core/` — this file, `docs/`, `config/`, `bin-private/` — is the overlay and stays private. `bin/` is symlinked into `~/bin` and the overlay's `home/` into `~`, so edit in the repo, commit, push.
- **Autonomy is the norm.** Sessions and agents decide and act on their own — the owner is interrupted only for the approval list below or a decision genuinely only theirs. Needing them means an @-mention in Slack — that reaches their phone; a line in the terminal or a board row does not. Standing goals live in `~/.cc/state/<repo>/goals.md`; the loop between tasks is `~/WORKING.md`.
- **Rules.**
  - Planning sessions never commit on the default branch — a small fix of their own goes on a short-lived branch and through a PR like anything else. Track sessions never commit, push or merge; the hook commits for them.
  - The owner approves: merging to the default branch (unless they grant it standing — then review and run the gates first, and say what landed), deploying, spend over budget, host/network/service changes, anything destructive, anything sent outward in their name, anything that widens what a non-owner may do, and **anything that opens the box to the outside** — an SSH path, a port, a tunnel, a new connector or integration.
  - Never touch: the interface the current session arrived on, the rescue address `<rescue-ip>`, the hotspot SSID `<hotspot-ssid>`. No host firewall, no partitioning, no reboot or shutdown without an explicit go-ahead.
- **Lead with the TLDR.** Any update longer than a couple of lines opens with one or two: what happened, and anything that needs the owner. This holds in the terminal too, not just Slack.
- **Answer where you were asked.** A question typed in the terminal is answered in the terminal; only a message that arrived with a `<channel>` tag is answered into Slack.
- **Writing to the owner.** Slack is short and plain — what happened, what it means, what they need to decide. No paths, SHAs, diff stats or test counts unless they ask. Depth goes to the track journal (`~/.cc/state/<repo>/<track>/progress.md`), `docs/`, or the channel canvas, linked in one line.
- **Where things are explained.** `~/USAGE.md` the commands · `~/COMMS.md` reaching a project or agent · `~/RUNBOOK.md` getting in, and what to do when it breaks · `docs/DESIGN.md` of the generic tree (`core/` on an overlay box) why the system is shaped this way · `~/WORKING.md` what a session does between tasks · `docs/` this box's incidents and audits.
- Use subagents for large reads; journal before a handoff.
